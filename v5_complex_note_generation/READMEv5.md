# Typebeat AI Composer V5 (Transition Into Complex Generative Output) --- Completed on 02/23/2026

## Description: In this version, I aimed to validate my proof of concept regarding the systemic architecture of a **basic musical artificial intelligence**. This was the culmination of the initial Version 1.0 Chord Generator created in C, that I was able to create and iterate upon without relying on the architectural foundation of an external library such as **Music21**. This iteration's core feature was the progression of the program from a logic engine that generated notes based on a user's input under a set of rules to a basic artificial intelligence that generated a sequence of notes (Or chords if on the 'poly' track) based on a **Directed Acyclic Graph** built out using **Stochastic Logic**. The user's only inputs in this case are the ability to select a custom starting offset, and the choice to either generate a new note based on the AI's recommendation, or to save the file and exit the program. In the new 'GENRE_MAP', A specific genre profile ('pop_punk' for example) is built as a dictionary, with the keys being a note "node" and the values being a list of potential outcomes that determine the next note in the sequence. Each note in a list of outcomes has a (non-equal) chance of being selected and once it is, then selects a new outcome from it's own respective list. This process continues until the user chooses to stop generating notes and selects the option to 'save' the file, which lets the program proceed to the teardown phase, like in previous iterations. In terms of architectural conflict at this stage of the project, it was at this point in time that I began to realize the layers and complexity of building out such a model from scratch, and that a transition to an industry-standard framework like Music21 would ensure a more reliable foundation from which I could use to dedicate more time developing the AI, rather than the "under-the-hood" features that allow it to function. The core driver behind the decision to use Music21 moving forward was efficiency, as previous features like the note rest/duration, the mono-poly states, adding new MIDI tracks and the ability to transpose notes by accomodating for modal scaling (e.g. Changing the scale from C major to G major) ultimately needed to be remade or added as additional features to support the 'GENRE_MAP'. However, creating the engine itself was still an important exercise that not only allowed me to validate the theories suggested from my intuition, but understand how  early iterations of an industry-standard framework like Music21 was likely built. In conclusion, the "Chord Generator" experience proved to be a very valuable starting point for systems design in musical programming.

## Design Decisions: Replaced user input with AI-directed decision-making by building a **Directed Acyclic Graph (DAG)** in the form of a decision tree revolving around a randomly generated path of progression notes from the original root note (Done by using 'random.choice()' to select an outcome from the list associated with a note). Semantic refactoring of user-centric variables to fit more general musical data. This was done because at this point I found it increasingly tricky to keep track of the code I was creating, and where the changes were being made. Considerations to implement dynamic saving (Saving multiple files using 'datetime' library), but were ultimately omitted due to notion of wasted engineering, as the feature will eventually be implemented through **SQL integration** in the 6.0 Version. In terms of the basic 'GENRE_MAP' note transitions, only 'pop_punk' and 'jazz_blues' were selected as options for the user to pick, as they utilized common musical progressions (I-V-vi-IV "Golden Circle", and ii-v-I turnarounds respectively). Another reason to support the move to Music21 is the integration of motif recursion, as my current model only supports the generation of an acyclical motif. Despite having the ability to heavily influence the entropy of a motif the AI generates, an ideal scenario would be the move towards a no-entropy motif (Or minimal entropy with a recursive motif and the ability to fully influence variation), which Music21 can provide the base for. **Stochastic logic** was also implemented in my program at this stage by adding **Stateful Memory**, in which the 'last_note' is checked and logged as a state representing the current path node of the genre's progression.

## Other Details: 'last_note' and 'current_genre' were declared as global variables, then referenced again in 'main():' as a form of variable shadowing to support the previously mentioned **stochastic logic** as a "state transition", where the base case initializes the default state and each new case builds out an acyclic **Markov Chain** using the previous state and the next destination. Most customizable options available when user input had a higher degree of influence were omitted in this version and replaced with default states for the AI to use. This was done purely for functionality purposes, as once again, the first iteration of the AI was meant as a proof of concept then adapted to an industry-standard framework.
