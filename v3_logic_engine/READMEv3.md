# Chord Orchestrator v3 (The Music Sequencer) --- Completed on 02/19/2026

## Description: The third iteration of this project aims to turn the otherwise simple MIDI file generator into a logic engine, where a series of notes can now be generated under a more complicated set of inputs and conditions. The main difference in this iteration is the implementation of states and sequences, not only has the engine improved so the user can customize the duration of their chord, but also the rest time between one chord and the next. The engine can now product multi-step results, where each time a new chord is added is representative of a new state, and thus, a sequence is created from a sequential amalgamation of those states. The memory management of the MIDI file becomes more complex and gives the user more options in creating their MIDI file. As for progress towards the AI Progression Engine, the foundation is expanded upon to give the future AI a wider range of abilities to play actual music, as crucially, longer rests can now be designated. In addition, perhaps the most important feature being added to this version is the ability to handle multiple tracks, with a designated "treble", "bass" and "chord" layer respectively. However, a glaring issue the orchestration regarding the previously named "Note Profiles" presented at this stage was the notion that it would proceed as a hard-coded entity, creating a bottleneck for the user. In addition, there was a lack of user-side controls that allowed them to interact with the various tracks present on the song. These features went "under the hood" in Version 3.0 and were iterated upon to fit a more dynamic, and UX-friendly model in 4.0. 

## Design Decisions: The "Note Profile" was converted into a vertical stack, to allow for multiple tracks to function simultaneously. A crucial distinction was made at this stage, to divide the 'midiutil' variables into "song-specific" data, and "note-specific" data. This meant that the track, offset, tempo, duration, and rest would be universal, and applied to each layer (treble, bass, chord) regardless. However, data such as the volume, channel (instrument), and track were kept in the add_midi_chord helper function to reduce the scope and provide clarity for future iterations. This led to the identification of an inefficient use of the 'track' variable, where it was being repeated in both the main function and the vertical stack for the "Note Profiles". Crucially, the model offers the functionality of "saving", rather than just the "exit" option the previous version had. The teardown phase now returns an error message if the system is unable to save the file. here, the file is opened using a "wb" ("write binary") as the mode in order to preserve the data being written to the file in the exact state the code before it had designated. 

## Other Details: The complexity of the security checks had been increased with this iteration, with specific error outcomes being created for the 'user_note' and 'user_chord_type', directly using a search method within their respective hash maps to find a match between the user's input, and an existing key-value pair within. With the addition of a bass layer, the number 36 has now been designated to represent C2, which at a starting point, is 2 octaves lower than Middle C (60). Additional addNote functions were added for each of the new single-note layers. The data type of 'duration' and 'rest' were also set as float to accommodate for 8th and 16th notes (0.5 and 0.25 respectively). Finally, the offset has now become a "cursor" of sorts, where each new rest determines where the cursor will move to. As a note, a potential DAW-specific interpretation conflict (Or race condition) arises here called Note Monophony per Pitch, which in summary, causes two of the same notes that would normally overlap (Duration of note 1 exceeds point where rest ends and note 2 begins) to be unable to coexist when read in a DAW, as the first note overlapping will actually remove the second note instead.

## Dependencies: sys, midiutil, MIDIFILE
