# Chord Orchestrator v1 (C Project) --- Completed on 02/16/2026

## Description: As inspiration for this, I wanted a quick way to identify progression chords using an algorithmic approach. However, to create the foundation for that concept, the first step would actually be to determine which chords at a basic level would be associated with a specific note. I also wanted to break down the idea of chords into a numerical concept, which led me to research into the pitch-class set theory, which represents each note on a chromatic scale into an integer, from 0-11. This led to the "bridge" between music and math, where notes within a chord could be determined by the semitone intervals between them and thus, be algorithmically generated.

## Design Decisions: This C program generates 3 types of chords based on the note a user types in (Major triad, minor triad, dominant 7th). It utilizes 'malloc' for the exact size of 3 and 4-note chords. Each musical note in the chromatic scale is mapped to an array called 'map[]', which are then compared to a user's input. If the user enters a correct note, it generates the 3 types of chords based on their input, showing each of the notes that they are comprised from. The pitch-class algorithm is being utilized to differentiate between each class of chord, transforming the user's input into 3 different types of output by looping through each note in a chord type, and applying a formula that adds the number of semitones as an interval, and using a modulo operator to limit the final value of the note to the range of 0-11 designated by the 'map[]' array. The chords are declared as fixed arrays based on the number of semitones between each note determined by the pitch class theory (Ex. 'maj_f' needs the values of 0, 4, and 7 hard-coded because the first note of this triad chord has to match the value of the designated input. The second note would then be 4 semitones higher, so an interval of 4 added and the third is the same but with 7 semitones). Finally, each chord type and their corresponding notes for the user's input are printed out and the instances of allocated memory are freed.

## Other Details: The struct 'Chord' at the beginning is essentially the "profile" of each chord type, with a name, note, and number of notes. The number of notes ('Chord.num_notes') do not require a pointer, as it is a fixed integer and doesn't require dynamically allocated memory, unlike 'Chord.notes', where the values within could be different while the 'Chord.name' is a string literal, therefore also not requiring 'malloc' in this specific case. There also needed to be an additional check for invalid user inputs that returned an error to prevent outstanding cases. If the user's input matches a value in the chromatic scale 'map[]', there should be an out (The 'break;') to exit the loop, since there only needs to be one successful outcome to find the initial note to generate chords for. 'root_index' was also declared as '-1', because it serves as a sentinel (Or default) value in a function where the condition is that we are looking for a number from 0-11. This means that if the default is negative, it would automatically exit the function if no matches were found. 'strcspn' was used to prevent the computer from storing '\n' values from the user's input, since 'stdin' was also being used to map a user's keyboard inputs to the program.
